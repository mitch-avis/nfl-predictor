## The dry-run warning (an addition nobody asked for)

A `--dry-run` that would refresh first does no refresh, so the file it reads is not the one the
real run would train on, and stopping there would be wrong. I accept the warning, for these
reasons:

- **A real run cannot skip every check.** Every non-dry run calls the early check with
  `stop=True` (`stop = args.skip_data_refresh or not args.dry_run`), after the refresh, on
  `args.data_path`. The check returns without stopping in only three cases, all of them by
  design:
  - the groups don't include `strength`;
  - the data has no strength columns;
  - the dataset is missing, and `_start_run` then raises `Missing dataset`.
- **A resumed run cannot skip it either.** `main()` runs the early check whatever the stage
  markers say, and stage 1 (including `write_reused_predictions_source`) and the final fit check
  again on their own frames.
- **The web jobs follow the same path.** The weekly job runs the same `main()`, and the
  walk-forward job runs `backtest`, which warns as the contract asks.

My adversarial test `test_a_real_run_on_old_data_stops_before_the_run_directory` (a `--resume`
run on old data) passes. It stops before `run/` exists.

The addition should still go on the user's list as an extra the task text did not ask for. I am
highly confident in accepting it.

## The dataset path

The weekly run has no `--data-dir`, only `--data-path` (`weekly_run/config.py:220-224`) and the
config's `data_path` key. The early check, `_start_run`, stage 1 (`pipeline.py:384,390`) and the
final fit (`pipeline.py:441`) all read `args.data_path`. My tests show:

- the config's `data_path` is read;
- `--data-path` overrides the config both ways: old data on the command line stops, and good data
  on the command line passes even when the config names old data.

The web weekly job passes `--data-path <settings.data_dir>/completed_games_ml.csv`
(`api/jobs/catalog.py:206-209`). The check therefore reads exactly what the run trains on.
