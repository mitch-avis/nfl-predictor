## Findings

### P2-1: nothing warns when a dataset has no `ratings` columns

The defaults drop the strength snapshot on the assumption that the ported ratings replace it,
but no code checks that the `ratings` group has columns. The main checkout's
`data/completed_games_ml.csv` has 513 columns and none from `ratings` (the candidate build has
541). So `nfl-predictor train` on today's data, a weekly run with `--skip-data-refresh`, and the
web train and walk-forward jobs would all train with neither strength nor ratings, and log only
"Feature groups left out of training: [...] (14 columns dropped)". The rebuild planned for the
merge session prevents this, but nothing enforces it.

Fix (test first): in the production entry points, when the groups left out include `strength`,
warn, or refuse to run, if `feature_spec.resolve_feature_group_columns(columns, ["ratings"],
warn_unmatched=False)` is empty. My test `test_a_default_fit_on_data_without_ratings_columns_warns`
fails today.

### P2-2: a backtest with no group option now measures something different

The default change itself is correct. Explicit lists keep their old meaning, because a list
replaces the default. A backtest without the option does not. That covers recorded commands
for older arms run without the flag (`.agents/guardrails.md:118`, the step-4 reference and the
tree-budget ladder in `.agents/benchmarks.md`) and the web walk-forward job. Such a run now
leaves out three groups and reproduces nothing recorded before. Checkpoints are not at risk,
because the config is part of the fingerprint.

Fix: one line in `.agents/benchmarks.md` and `.agents/walk_forward_runbook.md` saying that runs
recorded before this version reproduce with `--disable-feature-groups ''`. The delegating session
owns `benchmarks.md`.

### P3-3: some doc examples still assume the old empty default

- `README.md:773`: the ablation example `--disable-feature-groups pbp` also brings back `strength`
  and both own-Elo groups, so it is no longer "everything else identical" next to a plain
  `nfl-predictor backtest`. The README says so 15 lines later, but the example should read
  `--disable-feature-groups strength,own_elo,own_elo_wt,pbp`.
- `README.md:636`, `README.md:1530` and `.agents/modeling_spec.md:85` give the
  no-market-information recipe as `elo,own_elo_wt`, while the edited README section gives
  `strength,elo,own_elo,own_elo_wt`. That longer list is what the reviewed
  `ratings_marketfree_seed*` runs used: their metadata records `[strength, elo, own_elo,
  own_elo_wt]`. Say which is meant: the historical test bench, which keeps `strength`, or
  production without market information.

### P3-4: group lists keep their order and duplicates

`--disable-feature-groups own_elo_wt,strength,own_elo` gives stage hashes `f501a0df`/`be11e0d1`
instead of `e50d0fc8`/`25ef09c0`, so a run directory with the same groups listed in another order
retrains instead of resuming. A config listing `strength` twice is accepted and recorded with the
duplicate. `production_settings` already treats the order as no difference: my test passes. This
behavior predates the branch. Fix: reject duplicates in `feature_spec.validate_feature_groups`;
normalizing the order is optional.

### P3-5: a vector sigma raises `TypeError`, not `ValueError`

`floor_sigma.py:127` calls `math.isfinite(sigma)`. A `pd.Series` or an array with more than one
element raises `TypeError` instead of `ValueError`. Every caller today passes a float
(`weekly_home_win_prob`, `margin_to_home_win_prob`, `betting_report`), so the contract's
"elementwise if vectorized" does not apply, and I do not count this as a narrowing. Numpy scalars
and 0-d arrays are handled correctly. If vectors should be accepted: check
`np.all(np.isfinite(s)) and np.all(s > 0)` on `s = np.asarray(sigma, dtype=float)`.

### P3-6: a config key with no value turns every group back on

The weekly config reads `disable_feature_groups:` with no value as no group
(`weekly_run/config.py:146`), while a missing key gives production's three. Commenting out the
three list items but not the key brings `strength` and both own-Elo groups back without a
message. This predates the branch but matters more now. Fix: treat `null` as an error, or say it
in the config comment.

### P3-7: every walk-forward checkpoint is invalidated

`ml/floor_sigma.py`, `ml/feature_spec.py` and `constants.py` are all fingerprinted. The handoff
groups this chunk with `5284db2`'s fingerprint change (rule 14), so this is expected. The first
weekly run after the merge recomputes every stage-1 fold, and the stage markers change anyway.

### P3-8: no CHANGELOG entry or version bump on the branch

The handoff gives these to the delegating session. This is a changed default, so it needs a
minor bump.

### P3-9: the production default fit's predictions are not pinned

The characterization snapshots pin the no-group fit. The three-group default fit is covered by
columns and metadata, not by prediction values. That is optional, and only worth adding if the
snapshots are meant to guard the production fit.
