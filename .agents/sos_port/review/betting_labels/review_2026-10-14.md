## Findings

### P2

1. `.agents/sos_port/betting_labels.py:195-201` and `:729-731`. An empty governing set produces
   NaN bounds, which `apply_rule` classifies as "contains zero", so the run writes a keep-labels
   outcome (and non-standard `NaN` into the JSON) instead of stopping. It cannot affect this run
   (815 games), but a future build with no clean season would produce a silent false outcome.
   Fix: raise in `run` when `governing_games == 0`, and make `apply_rule` reject non-finite
   bounds, behind the failing test above.
2. `tests/test_sos_port_betting_labels.py:392-403`. The end-to-end test asserts only that the
   branch is one of the three names, so a wiring error (wrong column, wrong game set, one seed
   read twice) would pass. Fix: pin `record["rule"]["mean"]` and `games` to a hand computation,
   as `test_each_fold_uses_its_own_week_sigma` does.

### P3

1. `.agents/sos_port/betting_labels.py:138-142`. The interval depends on game order (here sorted
   by game id). Neither the protocol nor the report states the order. The decision is robust (20
   random orders all contain zero), but an independent rescore matches only if it sorts the same
   way. Fix: state "games in game-id order" in the report's instrument sentence and in future
   protocols.
2. `.agents/sos_port/BETTING_LABELS.md:139-144`, `betting_labels.json` `provenance.command`, and
   `.agents/sos_port/decisions/betting_edges.md:195-202`. The recorded and quoted command omits
   `--earlier-market-lines-metadata` (the default was used, and its hash is recorded), while the
   reproduce block includes it. The two give the same output. Fix: regenerate with the full
   command, or leave as is.
3. `.agents/sos_port/decisions/betting_edges.md`, entry 3. It does not cite the earlier
   spread-versus-moneyline tie (`+0.00075`, `-0.00086` to `+0.00237`) that the protocol lists as
   known before the run. Fix: one sentence pointing to the protocol's "Known before writing this"
   section.
4. `.agents/sos_port/betting_labels.py:512`. `RUN_DIRS` is zipped against whatever
   `--checkpoint-dir` values are given, with `strict=False`, so a run on other checkpoints would
   still label them `models/step6/ratings_anchored_seed*`. Fix: derive the label from the
   manifest, or print the run directories only for the defaults.
5. `.agents/sos_port/decisions/betting_edges.md:208`: entry 3 says "Review: not yet reviewed".
   Update it to name this review when the numbers are adopted.

## Questions for the user

1. **Which top-decile ranking should a future report use?** Today the report gives two: games
   ranked by the two-seed mean of `|edge|` (or `|beyond|`) and scored on the two-seed mean `d`,
   and games ranked by each seed's own magnitude and scored on that seed's `d`. The protocol said
   only "the top decile of `|edge|`". Recommendation: the two-seed mean ranking with the two-seed
   mean `d`. It matches rule 13 (seeds combined per game before bootstrapping) and gives one
   number per question instead of two. The per-seed rows can stay as a robustness note. The cost
   is that games near the decile cut can swap in and out with seed noise; with 82 games that is
   small. Confidence: medium-high. A protocol that wants labels judged as one production seed
   would see them would change my mind.
2. **Adopt the label test's outcome (labels stay on the whole edge)?** Recommendation: yes. It is
   the rule's own branch, reproduced exactly. Confidence: high.
