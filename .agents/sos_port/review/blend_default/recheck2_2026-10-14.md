## Questions the coordinator asked me to judge

### Can the manifest match pick the wrong folder?

A folder from a compared configuration that is not production is not matched: its config differs
(my test flips `market_anchor` on a copied manifest with the same shape, and the real folder is
still the one found).

- On disk, the multi-folder run directories (`weekly_2026_week_02*`, `week_03_*`) hold compared
  configurations of an older schema. Their configs differ in `calibration`, the
  `market_prob_*` fields, `wf_start_week` and the XGBoost parameters, so they match nothing.

A wrong pick needs all three of these:

- a folder with the production config and the same row and column counts that is not the run's
  own;
- the run's own folder deleted;
- the stage-1 reuse check still passing.

My test `test_the_only_match_is_taken_even_when_it_is_not_the_runs_own_folder` shows the code
then points at the stale folder. When the run's own folder is present, a stale twin gives two
matches and a warning, which is safe. The stale twin can only come from an earlier stage 1 in the
same run directory on the same production config and data shape: for example a stage 1 that was
interrupted, then rerun on other code. Stage-1 reuse also requires the same dataset hash, so the
stale folder's data would have to differ only in values, not in shape. I rate this P3 (finding 1).

### The implementer's stated limit (device and thread count)

The limit is real for the device and moot for the thread count:

- **Device:** the stage-1 reuse hash records the requested device (`auto`), while the manifest
  records the resolved one (`cuda` or `cpu`). If `auto` resolves differently on resume, nothing
  matches and the run warns (my test `test_an_auto_device_that_resolves_differently_finds_no_folder`
  confirms).
- **Thread count:** `n_jobs` comes from `xgb_n_jobs` or the code default
  `DEFAULT_XGB_PARAMS["n_jobs"]` (24), not from the machine. It is part of the stage-1 options,
  so a different count changes the reuse hash: stage 1 reruns and never reaches the lookup.

The remedy the warning names, `--no-resume`, reruns every stage. You have accepted that.
