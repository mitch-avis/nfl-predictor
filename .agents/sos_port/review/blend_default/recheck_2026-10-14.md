## The commented-out method in the shipped config

Today `config/weekly_run.yaml:136` reads `# power_rankings_method: blend`, so the parser value is
`None` and `_requested_method` resolves it to `blend`. A default weekly run ranks exactly as
before: my test shows the shipped config and a config with `power_rankings_method: blend` give the
same `power_rankings_report_config` (method `blend`, same sources), so the reports-stage hash and
the output are unchanged. The only visible change is that the config file no longer states the
value as a setting, and `cli_surface.json` shows `null`.

Recommendation: accept it. A set value has to count as explicit for item 4 to work (a YAML
`blend` with the legacy flag must be refused), so leaving the key commented with the default
named beside it is the simplest correct form. The alternative, a sentinel value such as
`power_rankings_method: default`, adds a choice to the option for no gain. Fairly sure; I would
change my mind if something reads `config/weekly_run.yaml` to display the method (I found no
reader in `src/`, `web/src` or `scripts/`).

## Questions for you

1. **How should a resumed old run directory find its stage-1 folds?**
   - Today: `write_reused_predictions_source` (`stage1.py:111`) recomputes the fold directory
     name from the current code and libraries; for any run directory whose stage 1 ran on `main`,
     the name differs, so no pointer is written and the blend ranking skips with an error on every
     resume.
   - Recommendation: look the directory up by its `manifest.json` (production config, row and
     column counts equal), and write the pointer only when exactly one directory matches; warn
     otherwise. Cost: one small function and two tests, no `ml/` edit, no change to any output.
     The cheaper option is to document "rerun stage 1 for a run directory from before this
     change"; rerunning the walk-forward costs its full run time.
   - How sure: fairly sure the manifest lookup is right. I would change my mind if you never
     resume weekly run directories across a code update; then documenting it is enough.
2. **Accept the commented-out `power_rankings_method` in the shipped config?**
   - Today: the key is commented out, and the code default resolves to the blend; a default
     weekly run ranks and hashes exactly as with `blend` set (tested).
   - Recommendation: accept. Cost: the file shows the default in a comment rather than as a
     value. Fairly sure.
