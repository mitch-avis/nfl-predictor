## Findings

### P2

1. **A missing, partial or damaged reference run blocks the rankings in every week, though
   only week 1 reads it.**
   - Where: `src/nfl_predictor/reporting/power_rankings.py:1406-1413` and
     `src/nfl_predictor/reporting/rating_sources.py:661-684`.
   - What happens: `read_split_predictions` always loads and averages the reference runs, which
     are 2 x 328 fold files with every feature column, on every weekly run. Any error raises
     `RatingSourceUnavailableError`, so the rankings are skipped.
   - Evidence: the adversarial test
     `test_missing_reference_run_does_not_block_a_mid_season_week` fails.
   - Fix: read the reference only when `week < FIRST_FITTED_WEEK`. For weeks 2 and later, pass
     `reference=()` or read `current` alone. This also stops loading 656 joblib files each week.
2. **Skipping the default ranking also drops the projected standings, the run still exits 0, and
   a resume never retries.**
   - What happens: `_write_power_rankings` returns `[]` on `RatingSourceUnavailableError`
     (`src/nfl_predictor/weekly_run/pipeline.py:528-530`). That drops the projected standings too,
     although they do not depend on the method.
   - The reports-stage marker is then written as complete (`pipeline.py:584`). The marker's hash
     covers the source paths, not whether they exist, so `--resume` reuses stage 4 even after the
     missing source is restored.
   - Before this change only an opt-in method could fail this way. Now the published default can.
   - Fix:
     - log the skip at error level;
     - add the skip reason to the stage-4 marker;
     - do not treat that marker as reusable;
     - keep writing the projected standings.
   - Do not fall back to another ranking method. My tests confirm the branch never falls back:
     it raises instead.

### P3

1. **The fold reader now accepts folds without a `neutral` column, to suit a test fixture.**
   - Where: `src/nfl_predictor/reporting/rating_sources.py:481-482` (commit `ac4b8fe`).
   - What happens: a real fold without the column now silently fits neutral-site games as home
     games. My test `test_neutral_column_dropped_changes_the_model_rating` shows the ratings move.
   - This is not a rule-11 difference today. Both `models/step4_reference/adopted_seed{42,7}` folds
     carry `neutral`, and so does the production dataset the measurement read.
   - Fix: add `neutral` to `tests/weekly_fixture.py`'s game rows and revert the fallback, or log a
     warning when the column is absent.
2. **An explicit `--power-rankings-method blend` with `--legacy-franchise-fit` now silently
   becomes Bradley-Terry.**
   - Where: `src/nfl_predictor/weekly_run/config.py:891-894`.
   - What happens: the code cannot tell an explicit `blend` from the default. Before this change,
     an explicit method other than Bradley-Terry with the legacy flag was refused.
   - Evidence: the adversarial test `test_explicit_blend_with_the_legacy_fit_is_refused` fails.
   - Fix: give the option a sentinel default (`None`) and apply the default after the legacy check,
     or document the behavior.
3. **The weight is fixed at 0.5 for every ranked season.**
   - Where: `src/nfl_predictor/weekly_run/config.py:47`.
   - The measured rule gives 0.7 for 2008-2009 and 0.6 for 2012-2014. This only matters when an
     earlier season is ranked again.
   - Fix: document it in the config comment.
4. **Stale "market-free" wording that the help text change missed:**
   - `config/weekly_run.yaml:56-57` (the `wf_market_mode` comment);
   - the warning at `src/nfl_predictor/weekly_run/config.py:719-723` ("a market-free run trains
     with no market transform").

5. **A resumed run from before this change has no `wf_compare/metadata.json`.**
   - Where: `src/nfl_predictor/weekly_run/stage1.py:347` writes the pointer only inside
     `evaluate_production`.
   - What happens: a run directory whose stage 1 was finished before this change and is reused on
     resume has no pointer, so the rankings skip.
   - Fix: write the pointer on the reuse path too.
6. **Weak test and a stale helper name.**
   - Where: `tests/test_market_free_runs.py`.
   - `test_a_run_without_game_lines_logs_its_note_at_info_level` asserts only that no warning is

   - The helper `_spec_warnings` now returns info notes.
