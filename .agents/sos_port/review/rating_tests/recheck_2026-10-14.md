## 5. Findings

No P0, P1 or P2.

### P3

1. **Check 8 verifies the recorded count, not the fit.** `check_calibration_rows`
   (`qb_plays_test.py:1397`) reads `training_rows`, which `calibrate` sets to the same `start`
   it slices with. A calibration that fits on its own week (`design[:end]`) but records `start`
   passes the check (adversarial test 1). The leak is guarded by the unit test
   `test_calibrate_fits_each_week_on_earlier_rows_only`, so nothing leaks today, but the report
   line (`:2121`, "were each fit on exactly the rows of the earlier weeks") claims more than the
   check shows. Fix: either word it as "recorded exactly the earlier weeks' row count", or
   refit a sample of weeks on the earlier rows and compare coefficients.
2. **No test that `run_integrity_checks` runs check 8.** Replacing the call with a plain count
   leaves all 58 quarterback tests green. Fix: a test on the synthetic league that tampers with
   `calibrate` and expects `run_integrity_checks` to raise, or asserts the count it returns.
3. **The perturbation has blind spots.** `perturbed_numbers` (`rating_tests_common.py:285`)
   leaves a float of exactly 1.75 unchanged (the fixed point of `7 - 3x`) and a null unchanged;
   the team check (`team_plays_test.py:494`) does not flip `is_home`, so a snapshot reading later
   sites passes. The contract asked only for numeric columns in the team check, so this is not a
   narrowing, and a leak reading any sum of later values is still caught. Fix: use a
   perturbation without a fixed point (for example `x + 7.5` for floats), fill nulls, and flip
   later sites in the team check too.
4. **The commit does not mark a dirty tree.** `git_commit` returns `HEAD` even when the scripts
   are modified, so a run on uncommitted code records a commit whose code differs; the code
   SHA-256 in the same block does catch it. Fix (optional): append `-dirty` when
   `git status --porcelain` lists the scripts.
5. **One-season t interval is NaN** (pre-existing, outside the fix range):
   `season_t_interval` with one season returns NaN bounds instead of raising. The reports use 19
   seasons. Fix: raise when fewer than two seasons.
