## 2. Findings

### P2

1. **The quarterback test prints an integrity check it never runs.**
   - Where: `.agents/sos_port/qb_plays_test.py:2087` prints "every calibration used earlier
     weeks only" as a fixed string. `run_integrity_checks` (`:2357`) never compares `calibrate`'s
     `training_rows` with the count of earlier rows.
   - The protocol's check 8 asks for that comparison, and the team test runs its equivalent
     (`team_plays_test.py:895`, `check_margin_rows`).
   - Not a leak: `calibrate` (`:737-767`) fits on `design[:start]` over rows sorted by season and
     week, and `test_calibrate_fits_each_week_on_earlier_rows_only` pins that.
   - Fix: add a `check_calibration_rows` that asserts `training_rows` equals the cumulative count
     of earlier (season, week) rows per candidate and raises `IntegrityError`, then print its
     result.

2. **Three fix commits landed without a failing test first** (test-first rule).
   - `983bdb2`: the JSON trailing newline.
   - `fe36d58`: the table dash and the stripped play text in `botched_snaps.py:481,495`.
   - `d368845`: scientific notation in `qb_plays_test.py:1953-2025`.
   - All three are report formatting only.
   - Fix: add tests that the JSON ends with `\n`, that an empty table cell is `-`, and that
     `_interval_text` keeps a 1e-5 difference visible.

### P3

1. **A cycle of wins is resolved silently.**
   - Where: `qb_plays_test.py:326`. When every candidate is beaten (A beats C, B beats A, C beats
     B), `decide` falls back to `order[0]` without saying so.
   - The protocol has no branch for this, so under guardrail 12 it should go to the user.
   - It cannot happen in this result: there are no wins at all.
   - Fix: return no recommendation, or raise, and have the report say the result lies between the
     rule's branches.
2. **A play can count twice in "every quarterback play".**
   - Where: `qb_play_parts`, `qb_plays_test.py:147,174`. A run flagged `qb_scramble`, `rush` and
     `aborted_play`, with the same quarterback as rusher and charged fumbler, lands in both
     `scrambles` and `charged_aborted`.
   - In 2005-2025 the cache holds 0 such plays, so no number changes.
   - Fix: add `& ~_flag("qb_scramble")` to the charged-botched condition, or the reverse.
3. **The information-set checks do not change every column**, while both protocols say "every
   row".
   - The quarterback check (`_perturbed_inputs`, `qb_plays_test.py:547`) leaves `point_margin`,
     `st_*` and `is_home` of later games untouched.
   - The team check (`_perturbed`, `team_plays_test.py:495`) leaves `st_plays` untouched.
   - The production code filters to earlier weeks before fitting, so nothing leaks. The checks
     are just weaker than written.
   - Fix: change every numeric column from week w on.
4. **A missing season gives a bare `KeyError`.**
   - Where: `rating_tests_common.py:317`, `season_t_interval`. `season_bootstrap` raises a clear
     `ValueError` in the same case.
   - Fix: the same guard as `season_bootstrap`.
5. **Two provenance and reproducibility gaps.**
   - No JSON record carries the git commit. The team tests' JSON also lacks the command and
     runtime (`team_plays_test.py:1407`). The commits are named only in the decisions file.
   - Descriptive extras differ in the last bit between runs: margin slopes, moved-EPA sums,
     calibration coefficients and spread means, at most about 4e-16 relative. "Identical numbers"
     in the decisions file holds for every decision value.
   - Fix: record `git rev-parse HEAD` in each provenance block.
